Комплект перенесён не как догма, а как набор правил против drift — расхождения между кодом, данными, требованиями, архитектурой и документацией.

## 1. Что перенесено в рабочий проект

| Идея bootstrap | Где живёт в МАВИТА-ШОП |

| Контракт агента и две паузы | `PROJECT_CORE.md` §2 |
| Единый источник фактов | `PROJECT_CORE.md` §4, `DOCS.md` |
| Реестр документов | `DOCS.md` |

| Стартовый промпт Ф0 | `docs/project-bootstrap/prompts/phase-F0-skeleton.md` |

## 2. Что не заводилось как рабочий документ

Не созданы рабочие:

- `docs/environments.md`;
- `docs/operations.md`;
- `.env.example`.

Причина: магазин пока не имеет кода, стендов и деплоя. Пустые документы создают ложное ощущение процесса. Шаблоны лежат в `templates/` и материализуются при появлении предмета.

## 3. Как пользоваться

Для новой работы агент сначала читает:

1. `PROJECT_CORE.md`;
2. `DOCS.md`;
3. `architecture.md` и релевантную спецификацию из `docs/specs/`;
4. `TESTING_PLAN.md`, если работа влияет на инварианты.

Для новой заметной фичи:

1. создать `docs/specs/<feature>.md` из `templates/spec.template.md`;
2. зафиксировать scope/non-scope;
3. добавить критерии приёмки;
4. обновить `DOCS.md`.

Для начала Фазы 0 (скелет кода):

1. использовать `prompts/phase-F0-skeleton.md`;
2. создать readiness-гейт одной командой;
3. обновить `PROJECT_CORE.md` и `TESTING_PLAN.md` по факту.

## 4. Главная дисциплина

- Контур безопасности и инварианты — раньше фич.
- Вертикальный срез — раньше ширины.
- Один факт — один дом.
- Инвариант без теста — долг, а не защита.
- Внешний мир (Робокасса в prod, реальные деньги) — только после явного подтверждения.
- Консеквентный выбор: варианты + рекомендация, не молчаливое решение.
