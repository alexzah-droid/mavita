# МАВИТА-ШОП environments

> Создать как `docs/environments.md`, когда появится первый внешний стенд (VPS).
> До этого канонический факт: окружение одно, локальная машина, см. `PROJECT_CORE.md`.

## Стенды

| Термин | URL | Где живёт | Деплой |
| --- | --- | --- | --- |
| Локальный | `http://localhost:3000` | машина разработчика | `npm run dev` |
| Production | `https://<domain>` | VPS Ubuntu 24.04 | только после Паузы 1 |

## Инварианты окружений

- Production под версионным контролем с первого дня.
- Никаких ручных правок на VPS, которых нет в репозитории.
- `ROBOKASSA_TEST_MODE=true` всегда, кроме явно подтверждённого prod.
- У каждого стенда свой `.env` со своими секретами.
- Любое действие на production требует Паузы 1.
- Миграции: локально → production после backup.
- Перед миграцией production-БД — `pg_dump` backup.

## Секреты

- Реальные `.env` не коммитятся.
- `.env.example` — единственный публичный список переменных.
- Секреты хранятся: `<где — 1Password / Vault / вручную на сервере>`

## Запреты на production

- Не запускать `psql` с ручными `UPDATE`/`DELETE` без backup.
- Не выставлять `ROBOKASSA_TEST_MODE=false` без явного подтверждения владельца.
- Не деплоить без прохождения readiness-гейта.
