# Спека: виджет СДЭК с картой (выбор ПВЗ) — Фаза 2

**Статус:** план, к реализации после получения ключа Яндекс.Карт. Точный
wire-протокол `servicePath` и поля `onChoose` сверить с эталонным `service.php`
и `@cdek-it/widget` **при реализации** (на память не полагаемся — как с
`city`/`city_code`, см. ниже).
**Дата:** 2026-06-24.
**Предшествующее:** СДЭК-ПВЗ уже живой на проде через кастомный автокомплит
города + список ПВЗ (фикс `city_code`, заказ №13 проверен). Это путь C из
[delivery-options.md](delivery-options.md): «список сейчас → виджет потом».
**Источники:** [cdek-it/widget](https://github.com/cdek-it/widget),
[типы виджета 3.x](https://cdn.jsdelivr.net/gh/cdek-it/widget@3.11.1/dist/cdek-widget.es.d.ts),
[Next.js-интеграция (disa4148)](https://github.com/disa4148/cdek-widget-3.0),
[тарифы Яндекс.Карт](https://yandex.ru/maps-api/tariffs).

## Цель

Заменить кастомное поле города + `<select>` ПВЗ на **интерактивную карту-виджет
СДЭК**: поиск города, карта с пунктами, фото/часы/фильтры, кнопка «рядом со
мной». Виджет возвращает **стабильный код ПВЗ** в колбэке. Это лучший UX и
снимает ручной ввод города. Модель заказа, цену и серверную валидацию **не
меняем**.

## Ключевые решения

| Вопрос | Решение |
|--------|---------|
| Роль виджета | **Только выбор ПВЗ** (`offices`). Цена доставки — НЕ из live-расчёта виджета |
| Источник цены | Остаётся серверный фикс-тариф `store_settings` (сейчас 50₽). Инвариант `total = items + delivery` и `409 PRICE_CHANGED` сохраняются без изменений |
| Проксирование СДЭК | `servicePath` = наш роут `/api/cdek/widget`, ходит в СДЭК с нашим OAuth (как `lib/cdek.ts`). Ключи СДЭК на клиент НЕ попадают |
| Ключ Яндекс.Карт | Клиентский, ограничен доменом `mavita.ru` в кабинете Яндекса; в env как `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` |
| Результат выбора | `onChoose` → сохраняем код/город/название/адрес в **существующий** snapshot `pickup_point_*`. **Миграция БД не нужна** |
| Ре-валидация | `getPickupPoint(code)` в `createOrder` остаётся — код из виджета проверяется сервером перед оплатой |
| Способы | На этой фазе **только ПВЗ** (без курьера/постаматов), как и сейчас |
| Деградация | Нет ключа Яндекса / виджет не загрузился → **fallback на текущий автокомплит города + список ПВЗ** (не теряем рабочий поток) |

> **Почему цену берём не из виджета:** наш заказ хранит неизменяемый серверный
> `delivery_kopecks`, и сумма к оплате считается на сервере. Если позволить
> виджету диктовать цену live-расчётом, разойдётся с серверным снапшотом и
> сломается логика `PRICE_CHANGED`. Виджет — инструмент **выбора точки**, а не
> источник цены. Live-расчёт СДЭК до оплаты — отдельное будущее решение.

## Как получить ключ Яндекс.Карт и какой тариф

1. Зарегистрироваться в **Кабинете разработчика** Яндекса:
   https://developer.tech.yandex.ru/ → выбрать **JavaScript API** → «Подключить
   API» → сгенерировать ключ.
2. **Ограничить ключ доменом** `mavita.ru` (HTTP Referer) в кабинете — ключ
   клиентский, ограничение домена не даёт использовать его на чужих сайтах.
3. **Тариф:**
   - **Бесплатный** — **500 запросов в сутки** при выполнении «условий
     бесплатного использования» (сервис публичный и бесплатный для пользователя,
     показывается атрибуция/лого Яндекса). Для старта магазина этого с запасом
     (500 загрузок карты в день = 500 открытий виджета).
   - **Коммерческая лицензия** — **195 000 ₽/год** (Standard), сверх лимита
     **390 ₽ за каждые +500 запросов/сутки**; больше — «напишите нам».
   - **Рекомендация:** стартуем на **бесплатном** тарифе; перейти на
     коммерческий — только если упрёмся в лимит или условия бесплатного
     использования не подойдут под наш кейс (проверить условия до запуска).

## Технический контракт

### 1. `servicePath` — роут `/api/cdek/widget` (протокол сверен с эталоном)

Точный протокол снят с эталонного `dist/service.php` (`cdek-it/widget@3.11.1`).
Запрос = merge(query, JSON-body); обязателен `action`; перед вызовом — OAuth.
Тело ответа СДЭК отдаём **как есть** (виджет парсит нативный JSON, без обёртки):

| `action` | Метод и эндпоинт СДЭК | Параметры | Ответ |
|---|---|---|---|
| `offices` | `GET /v2/deliverypoints?<params>` | все параметры запроса как query | массив точек СДЭК verbatim |
| `calculate` | `POST /v2/calculator/tarifflist` | merge(query, body) как JSON | ответ калькулятора verbatim |
| иначе | — | — | `400 {message:'Unknown action'}` |

- Авторизация: `POST /v2/oauth/token` `grant_type=client_credentials` — это уже
  делает `accessToken()` в `lib/cdek.ts`, переиспользуем.
- Доступ только при включённом cdek (`getRuntimeCredentials('cdek')`); иначе 503,
  и клиент уходит в fallback. IP-лимит (`lib/public-rate-limit.ts`).
- `calculate` проксируем честно (виджет функционирует), **но списываемая цена —
  НЕ из него**: заказ всегда хранит серверный фикс-тариф `store_settings`
  (сейчас 50₽). Виджет настраиваем PVZ-only; цену в виджете прячем, в нашем итоге
  показываем 50₽. Если виджет всё же покажет оценку СДЭК — это его ETA, а
  списывается фикс-тариф (визуально сверить на проде, при путанице — донастроить).

### 2. Клиент — компонент карты
- Скрипт: `@cdek-it/widget@3` (npm или `cdn.jsdelivr.net/npm/@cdek-it/widget@3`,
  `next/script` `beforeInteractive`).
- Инстанс в `'use client'`-компоненте чекаута:
  ```
  new CDEKWidget({
    root: '<id контейнера>',
    apiKey: process.env.NEXT_PUBLIC_YANDEX_MAPS_API_KEY,
    servicePath: '/api/cdek/widget',
    from: '<город отправителя>',          // для отображения/фильтра
    defaultLocation: '<город>' ,          // дефолт; опц. из IP, см. ниже
    hideDeliveryOptions: { door: true },  // только ПВЗ
    onChoose: (type, tariff, point) => { /* сохранить point.code и адрес */ },
  })
  ```
- `onChoose(type, tariff, point)` → берём `point.code`, `point.city`,
  `point.name`/адрес → кладём в состояние формы как текущий `pickupPoint`
  (тот же контракт, что сейчас отдаёт `/api/cdek`).

### 3. Создание заказа — без изменений
`robokassa/init` → `createOrder`: метод `cdek_pickup`, `pickupPointCode` из
виджета, серверная `getPickupPoint(code)` ре-валидация, снапшот в
`pickup_point_*`, `delivery_kopecks` = серверный тариф, `409 PRICE_CHANGED` при
расхождении. Существующая логика и тесты остаются.

### 4. env
- `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — клиентский ключ Яндекс.Карт (домен ограничен).
- Ключи СДЭК — уже в `store_settings` (шифр), новых секретов нет.

## Опционально: открывать виджет на городе покупателя (MaxMind)
Уже готовый `/api/checkout/city` + `lib/geoip.ts` (MaxMind GeoLite2) можно
использовать как источник `defaultLocation`: сервер по IP вернёт город, виджет
откроется на нём. Необязательно — без этого виджет открывается на дефолтном
городе и имеет свой поиск + геолокацию. Подключать после установки `.mmdb`
(см. operations.md, «Префилл города по IP»).

## Что заменяется в коде
- Кастомное поле города + автокомплит + `<select>` ПВЗ в `app/checkout/page.tsx`
  → контейнер виджета (для cdek). **Оставляем текущий поток как fallback**, если
  виджет/ключ недоступны.
- `/api/cdek/cities` и `/api/cdek?cityCode=` — становятся резервом (нужны для
  fallback и/или админ-проверки); не удаляем.
- `lib/cdek.ts` (`listPickupPointsByCityCode`, OAuth) — переиспользуется в
  `servicePath`.

## Безопасность и ПД
- Ключи СДЭК остаются на сервере (`servicePath` проксирует). Клиент видит только
  публичный ключ Яндекса (ограничен доменом).
- Виджет грузит сторонние скрипты (Яндекс.Карты, СДЭК) на клиенте — отметить в
  оферте/политике, что карта предоставляется Яндексом, данные ПВЗ — СДЭК.
- Персональные данные получателя в виджет не передаются — он только про выбор точки.

## Scope / Non-scope
- **В scope:** карта-виджет для выбора ПВЗ, `servicePath`-прокси `offices`,
  сохранение стабильного кода в snapshot, fallback на текущий поток, ключ Яндекса.
- **Не в scope:** курьер и постаматы; live-расчёт цены виджетом (цена остаётся
  фикс-тарифом); автосоздание накладной/трека (отдельная фаза); зоны/Москва
  отдельным тарифом; Ozon (удаляется, см. ozon-removal).

## Критерии приёмки
- [ ] На чекауте при включённом cdek и заданном ключе Яндекса рендерится карта с
  ПВЗ; поиск города и «рядом со мной» работают.
- [ ] Выбор точки заполняет snapshot (код/город/название/адрес); кнопка оплаты
  активна только после выбора.
- [ ] Цена доставки = серверный фикс-тариф; `total = items + delivery`; подмена
  на клиенте отбивается `409 PRICE_CHANGED`.
- [ ] `getPickupPoint(code)` ре-валидирует код из виджета при создании заказа.
- [ ] Нет ключа/виджет не загрузился → автоматический fallback на текущий
  автокомплит + список ПВЗ; оформление не ломается.
- [ ] Ключ СДЭК не виден в сетевых запросах клиента; ключ Яндекса ограничен доменом.

## Риски
- Точный протокол `servicePath`/`onChoose` 3.x — проверить на эталоне при
  реализации (не по памяти).
- Условия бесплатного тарифа Яндекса под коммерческий магазин — проверить до
  запуска; иначе коммерческая лицензия (195k₽/год).
- Виджет — сторонний клиентский скрипт: следить за версией `@cdek-it/widget@3`,
  не ломает ли CSP/перформанс. Fallback обязателен на случай недоступности.
